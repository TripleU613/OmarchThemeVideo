# Working in this repo

Rules for people and coding agents working on the film. The README explains how
the pipeline works; this file is what you must not break.

## Layout

- `analysis/` turns the song into timing data: `lines.json` (every sung word's
  onset and end), `audiomap.json` (beats, downbeats, kicks, snares, rolls,
  energy) and `drums.json` (the same drums and beats measured again on the song,
  on the attack; `refine_events.py`). Timing only; the words live in
  `music-video/lyrics.txt`.
- The song (`music-video/assets/audio/song.wav`) and its words
  (`music-video/lyrics.txt`, built into `assets/lib/lyrics.js` by
  `npm run lyrics:build`) are in the repo. The owner has permission to use both.
- `music-video/` is a HyperFrames composition, one JavaScript file per scene in
  `assets/scenes/`, with the shared engine in `assets/lib/`.
- `music-video/index.html`, `dev.html`, `play.html` and `STORYBOARD.md` are generated by
  `npm run assemble` from `storyboard/scenes.json` and the timing. Never edit them
  by hand.

## Rules for scenes

1. **One idea per line.** Each scene is a visual metaphor for its line, with a
   setup, a turn on the key word and a payoff. Never just the wordmark or a UI
   screenshot. The ideas live in `storyboard/IDEAS.md`.
2. **The words are the material.** A scene draws its own line's words with
   `OM.sung(id)` and calls `OM.ownWords.add(id)`. The words are what the idea acts
   on, never a caption; every word lands on its sung onset. Words stay whole and
   in frame: never under the 40 px border band, never covered or struck through
   by the scene's own props, and never with a stray shape in the gap between two.
3. **Words come from the lyrics file.** Scenes never hard-code the words: they
   draw their line through `OM.sung(id)`, so a fix in `lyrics.txt` (then
   `npm run lyrics:build`) reaches every scene. Refer to lines by id in code.
4. **Every frame is a pure function of song time.** The renderer seeks to any
   frame in any order. No `Math.random`, `Date` or `performance.now`; use
   `OM.rng(seed)` or `OM.hash()`.
5. **Cuts are invisible.** Every scene starts exactly on its incoming handoff and
   ends exactly on its outgoing one (`OM.handoff`, see `assets/lib/handoff.js`).
   Compare the frames 4 ms either side of the cut. On a still frame they must
   measure SSIM 0.99 or better. Through fast motion, such as a match cut in
   rain or flight, the pair across the cut must be no less similar than the
   8 ms pairs on either side. The only exception is a cut deliberately designed
   as a hit.
6. **Tokyo Night only**, from `OM.fieldInks('tokyo-night')` and `OM.theme(...)`.
   The White theme belongs only to the rented-world verse (v1-01 to v1-03).
   Everything is drawn as lattice light and clean silhouettes: never photoreal,
   no copyrighted characters, no replays of omarchy.org's own animations, and
   the wordmark is rationed to the naming lines and the bookends. No grain,
   scanlines, vignette, lens flare or ghosts, chromatic aberration, bloom haze or
   drop shadows (the full banned list is in `storyboard/WORKER.md`).
7. **Hit the music.** `npm run facts <id>` lists each scene's beats; the key word
   gets the biggest moment. The beat grid (`OM.T.beats`, `OM.T.downbeats`,
   `OM.beatsIn`, `OM.downbeatsIn`, and any number copied from them) runs about
   46 ms late against the drums, so a visible hit on a grid time goes through
   `OM.beatOnset(t)`, which returns that beat's drum onset. Kick and snare times
   in `assets/lib/frame-need.js` and word onsets are already on the drum. All
   analysis times sit on 23 ms frames, so about ±12 ms is as close as the data goes.
8. **Budget:** 12 ms per frame or less at 1080p in the dev player.
9. **Camera and effects belong to the scene.** Each scene runs its own camera
   move and shader through `OM.post` (its row in `storyboard/FX.md`). Effect
   amount is 0 on the cut frames, the camera is at rest at section boundaries, and
   the words stay readable. The shared layers are the edit camera (rule 10) and
   the frame effects (`assets/lib/frames.js`). They draw only in the outer border band, one idea per
   section, always all the way round, in scenes that leave an edge empty
   (`assets/lib/frame-need.js`), and subtler where only some edges are empty.
   Beneath them, a faint pixelated rim fog is always on: it breathes on the beat and
   takes the picture's edge colour. All of it is continuous across every cut.
10. **The edit camera cuts the film to the drums.** Over every scene, one shared
   camera (`OM.edit.stageAt`, the end of `assets/lib/kit.js`) moves the whole
   picture on the drums measured on the song (`OM.T.drums`, `OM.T.beatsOn`, from
   `analysis/refine_events.py`). It punches in on beats 1 and 3, jolts and rolls on
   2 and 4, hits harder on the beat that lands a cut, and builds through each fill
   into a downbeat (and the bar into each chorus), snapping off on the drop. It is
   one CSS transform on every live scene, so it runs straight through the cuts and
   both sides of a cut still match. Each section has its own strength. A scene
   tunes it only in its own window, with `OM.edit.plan(id, {...})` at the top of its
   file. Use `skip` for the scene's own hits so nothing stacks, a lower `max` where
   words sit near the border band (at peak they must still clear it), and
   `off: true` for a held moment. Seam checks on the raw scenes add `?edit=0` to
   the page URL. `OM.jiggle(T, ownHits)` still exists for one element that should
   bump on the beat, and `OM.edit.scene(...).clock(T)` gives a scene's own camera
   a time that surges through each beat.

## Working rules

- Agents building scenes follow `music-video/storyboard/AGENT-BRIEF.md`, for one
  scene or a whole section ("Section mode"), and touch only their own scene files.
- The CPU is shared. Run snapshots through
  `flock /tmp/omv-snap.lock nice -n 19 npx hyperframes snapshot ...`, never use all
  cores, and never start a final render without the owner's go-ahead.
- Never commit renders, snapshot caches or the placeholders (the silent song from
  `npm run audio:placeholder`, the words from `npm run lyrics:placeholder`).
  `.gitignore` and `npm run verify` enforce it.
- Before committing, run `npm run assemble` and `npm run verify` in
  `music-video/`. CI checks both.
