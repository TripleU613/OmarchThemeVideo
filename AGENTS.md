# Working in this repo

Rules for people and coding agents working on the film. The README explains how
the pipeline works; this file is what you must not break.

## Layout

- `analysis/` turns the song into timing data: `lines.json` (every sung word's
  onset and end) and `audiomap.json` (beats, downbeats, kicks, snares, rolls,
  energy). Timing only; it never stores lyric text.
- `music-video/` is a HyperFrames composition, one JavaScript file per scene in
  `assets/scenes/`, with the shared engine in `assets/lib/`.
- `music-video/index.html`, `dev.html` and `STORYBOARD.md` are generated by
  `npm run assemble` from `storyboard/scenes.json` and the timing. Never edit them
  by hand.

## Rules for scenes

1. **One idea per line.** Each scene is a visual metaphor for its line, with a
   setup, a turn on the key word and a payoff. Never just the wordmark or a UI
   screenshot. The ideas live in `storyboard/IDEAS.md`.
2. **The words are the material.** A scene draws its own line's words with
   `OM.sung(id)` and calls `OM.ownWords.add(id)`. The words are what the idea acts
   on, never a caption; every word lands on its sung onset.
3. **Never write lyric text anywhere in the repo**: not in code, comments, docs or
   commit messages. Words reach the screen only from the lyrics file you build
   locally (`assets/lib/lyrics.js`, which is gitignored). Refer to lines by id.
4. **Every frame is a pure function of song time.** The renderer seeks to any
   frame in any order. No `Math.random`, `Date` or `performance.now`; use
   `OM.rng(seed)` or `OM.hash()`.
5. **Cuts are invisible.** Every scene starts exactly on its incoming handoff and
   ends exactly on its outgoing one (`OM.handoff`, see `assets/lib/handoff.js`).
   Compare the frames 4 ms either side of the cut. On a still frame they must
   measure SSIM 0.99 or better. Through fast motion, such as a match cut in
   rain or flight, the pair across the cut must be no less similar than the
   8 ms pairs on either side. The only exception is a cut deliberately designed
   as a hit.
6. **Tokyo Night only**, from `OM.fieldInks('tokyo-night')` and `OM.theme(...)`.
   The White theme belongs only to the rented-world verse (v1-01 to v1-03).
   Everything is drawn as lattice light and clean silhouettes: never photoreal,
   no copyrighted characters, no replays of omarchy.org's own animations, and
   the wordmark is rationed to the naming lines and the bookends.
7. **Hit the music.** `npm run facts <id>` lists each scene's beats; the key word
   gets the biggest moment.
8. **Budget:** 12 ms per frame or less at 1080p in the dev player.
9. **Camera and effects belong to the scene.** Each scene runs its own camera
   move and shader through `OM.post` (its row in `storyboard/FX.md`). Effect
   amount is 0 on the cut frames, the camera is at rest at section boundaries, and
   the words stay readable. The one shared layer is the frame effects
   (`assets/lib/frames.js`). They draw only in the outer border band, one idea per
   section, always all the way round, in scenes that leave an edge empty
   (`assets/lib/frame-need.js`), and subtler where only some edges are empty.
   Beneath them, a faint pixelated rim fog is always on: it breathes on the beat and
   takes the picture's edge colour. All of it is continuous across every cut.

## Working rules

- Agents building scenes follow `music-video/storyboard/AGENT-BRIEF.md`, for one
  scene or a whole section ("Section mode"), and touch only their own scene files.
- The CPU is shared. Run snapshots through
  `flock /tmp/omv-snap.lock nice -n 19 npx hyperframes snapshot ...`, never use all
  cores, and never start a final render without the owner's go-ahead.
- Never commit song audio, lyrics, renders or snapshot caches. `.gitignore` and
  `npm run verify` enforce it.
- Before committing, run `npm run assemble` and `npm run verify` in
  `music-video/`. CI checks both.
